# 硬件与接口

## 设备

| 项 | 值 |
|---|---|
| 型号 | ZTE V9200 (ZXRAN 5G BBU) |
| 内核 | 4.19.82-rt30 |
| CPU | 多核 ARM64 |
| 管理口 | LMT，默认 `192.254.1.16/16` |

## PCIe 网络设备

```
0000:ec:00.0  Intel 8086:1896   Intel E800 魔改
             驱动: ice_sw 0.15.0_rc5_33
             产出 21 个 netdev

0000:01:00.0  Marvell 11ab:c81f
             内核无驱动（config 只有 e1000/e1000e/igb/ice，全内置无 .ko）
             由 HWM.EXE 以 mmap 直接操作
```

Marvell 那颗不受 Linux 网络栈管理，无法用标准工具配置。

## netdev 命名

`ice_sw` 产出的 21 个 netdev 里，与软路由相关的是：

| 接口 | 用途 |
|---|---|
| `eth16` | CPU 口 800 对应的物理口，WAN 方向 |
| `eth16.16` | 手动创建的 VLAN 16 子接口（宿主侧建） |
| `eth18`, `eth19` | 面板业务口，可做 LAN |
| `eth7`, `eth100`, `eth200` | 内部/虚拟口，默认 admin down |

`eth200` 是 Luban 中间件的虚拟口，不下发数据。

## 面板口实测

**四个面板业务口行为一致，都不能作为第二个 LAN 口。**

原因：CPU 口成员表 `[15:tag][16:tag][100:untag]` + `pvid=100`，面板口属于 VLAN 16，而 CPU 口入向是 untag。要让面板口当 LAN，需要重配 egress 矩阵，实测不可行。

替代方案：

1. USB 网卡（推荐）
2. 单 LAN + SSH 隧道

## CPU 口 VLAN 配置

```
成员表: [15:tag] [16:tag] [100:untag]
pvid:   100
```

- 入向（上游 → CPU）：物理链路上的帧带 VID 16，网卡 `rx-vlan-offload=on` 在进内核前剥离，所以 `eth16` 直接收到裸 IPv4/ARP
- 出向（CPU → 上游）：natd 从 `eth16` 发裸帧会被 `pvid=100` 归入 VLAN 100，到不了 VLAN 16 的端口 50

所以出向必须走 `eth16.16`。

## 指示灯

见 `docs/assets/V9200-indicators.md`（从厂商手册整理）。

| 灯 | 状态 | 含义 |
|---|---|---|
| PWR | 常绿 | 电源正常 |
| RUN | 慢闪 | 系统运行中 |
| ALM | 红 | 告警 |
| ACT | 闪 | 有业务流量 |

## 线缆

原厂配线为专用连接器。自制线缆时注意：

- 引脚定义随批次可能不同，**先量通断再接线**
- 电源线极性反接会烧板
- 建议用原厂线缆，自制仅作应急

## 散热

设备为基站级设计，风噪大。家用环境下建议：

- 放独立机柜或阳台
- 不可密闭放置
- 环境温度 < 35°C
