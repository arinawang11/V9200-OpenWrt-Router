# 硬件

适配的板卡是 **VSWD1**，装在 ZXRAN V9200 机框的槽位 1 上。

ZTE 官方手册里 V9200 是 5G BBU（基带单元）机框。机框里能插的板子：VSW 是交换板，VBP 是基带板，VEM 是环境监控板，VPDc1 是电源分配板，VFC1 是风扇模块。我们要用的就是 VSW 这块，具体型号 VSWD1。

## 插在槽位 1 上的这台，硬件是这样的

| | |
|---|---|
| CPU | Intel Atom P5962B（Snow Ridge），48 线程 |
| 内存 | 16 GB |
| 存储 | 32 GB SSD + 2 GB boot flash |
| 交换芯片 | Intel Snow Ridge IES（PCI `0000:ec:00.0`） |
| 加速卡 | Intel QAT c4xxx（`0000:f4:00.0`） |
| 协处理器 | Marvell（`0000:01:00.0`），无内核驱动 |
| 看门狗 | EPLD MMIO `0xFE0BF000` |
| SPI flash | MX25L25635E 32 MB |
| 整机功耗 | 估 40–80 W |

## 为什么这台机器当软路由挺香

**48 线程跑防火墙，性能不是瓶颈。** 普通软路由要么是家用小盒子（J4125 之类 4 核），要么是 x86 小主机（8~16 核）。这颗 Snow Ridge 是 48 线程，专门为网络负载设计的架构。跑满一个千兆对它是浪费。

**板载交换芯片是硬件交换。** Intel IES 是数据中心级的以太网交换硅片，不是靠 CPU 转发。21 个 netdev 都由它出，其中 `eth20` 是 100G 的 CPU 上联口，一直是 up 状态。芯片内部还有 8 个 10G 的 SoC 通道（`eth8`~`eth15`），开机就 PTP 同步，不对外暴露但可以用。

面板口给的是 **2×10G SFP + 2×QSFP + 1×RJ45**。QSFP 那两个口测不出链路（需要 QSFP 跳线环回验证归属），但如果能跑起来就是 40G 级别。RJ45 那个也没测。能确认的只有 ETH1/ETH2 两个 SFP 口是 10G。

**QAT 加速卡是白送的。** Intel QAT c4xxx，128 个 VF。原厂拿来给 5G 做加解密，转软路由之后基本闲置。OpenWrt 的 `intel-qat` 包可以直接用，给 IPsec VPN 提速。

**220V 家用插座直插。** 机框是双模供电设计：槽位 5 是 220V 交流板，槽位 13 是 -48V 直流板。家用只用 220V 那块就行，-48V 那块在位空载不亮灯是官方定义，不是故障。

**风扇和电源都不用管。** 风扇硬件自控温，重启时 fail-safe 全速转，没有软件控制路径。电源板 MCU 自保护。这两个都不需要你在 OpenWrt 里做任何事。

**16GB 内存 + 32GB SSD 装什么都够。** 除了跑 OpenWrt 容器，还能塞一堆 sidecar。

## 但有几个坑要知道

**看门狗会杀你。** EPLD `0xFE0BF000`，喂狗方式是往 `0xC8` 交替写 0/1，每 500 ms 一次，定时器在 `0xC4`（bit0 = armed）。**127 分钟没人喂就复位整机**。原厂的 `watchdogfeed` 进程退役后没在跑，所以你得自己喂。转 OpenWrt 的话必须内置这个逻辑。

**GNSS 没天线就废了。** 面板 GNSS 是 SMA 口，没天线收不到星。`/dev/pps0` 的源其实是 `ptp0`（交换芯片的 PTP），跟 GNSS 模块没关系。想恢复授时要配有源天线 + gpsd + chrony。

**RTC 电池没电。** 芯片是好的，断电就丢时间，运行期间正常。给 OpenWrt 配个 NTP 客户端就行。

**Marvell 那颗芯片不能碰。** `01:00.0`，`11ab:c81f`，内核无驱动，由 `HWM.EXE` 用 DPDK 用户态独占。**裸 devmem 读它的 BAR 会挂总线导致整机崩溃**，我实测过，机器直接复位。只能通过 HWM 初始化之后的 mmap 访问。

**串口没找到。** UEFI 走 `console=ttyS4,115200`（TI16750 @ `0000:00:1a.0`），但物理出口没定位。USB-C 是纯 host 口（dmesg 里没有任何 typec/ccg/ucsi 控制器），DBG/LMT 是纯网口（1000BASE-T 占满 8 针）。最可能是 VSW 板上的排针，得拆机看。BIOS 设置界面需要串口接入，所以现在进不去。

## 面板端口

丝印顺序：`ETH1(SFP) ETH2(SFP) ETH3(QSFP) ETH4(QSFP) ETH5(RJ45) DBG/LMT(RJ45) CLK(RJ45) GNSS(SMA) USB-C`

| 面板口 | 内核接口 | 实测情况 |
|---|---|---|
| DBG/LMT | `eth1`（1G 铜口，纯以太网） | SSH 可用。DBG 和 LMT 是两个逻辑通道复用同一物理口，不是串口 |
| ETH1 (SFP) | `eth18` 或 `eth19`（10G） | 光纤环回点亮，PTP synced |
| ETH2 (SFP) | `eth18` 或 `eth19`（10G） | 同上 |
| ETH3 / ETH4 (QSFP) | 未确定 | 需要 QSFP 跳线环回才能测 |
| ETH5 (RJ45) | 未确定 | 需要网线接入测试 |
| CLK | 不走以太网 | 时钟口（1PPS / 1588） |
| GNSS | 不走以太网 | SMA 天线口 |

`eth1`~`eth20`、`eth100`、`eth101` 全在 Snow Ridge IES 交换芯片上，由 `ice_sw` 驱动管。面板只引出了 6 个业务口，其余是芯片内部口和背板互联。

## 接口名是怎么来的

MAC 尾号 = IES 物理端口号 + 0x11。全部对得上 dmesg 的 rename 记录。

| IES Port | 接口 | 角色 |
|---|---|---|
| 0 | `eth100` | 内部管理口（原 eth0） |
| 1 | `eth101` | 内部管理口（原 eth1） |
| 2–7 | `eth2`–`eth7` | 面板候选：ETH3(QSFP) / ETH4(QSFP) / ETH5(RJ45) + 未引出口 |
| 8–15 | `eth8`–`eth15` | SoC 内部 8×10G 通道，开机即 PTP synced |
| 16 | `eth16` | 面板候选 |
| 17 | `eth1`（LMT） | 面板 LMT 1G 电口（原 eth17） |
| 18 | `eth18` | 面板 ETH1 SFP 10G |
| 19 | `eth19` | 面板 ETH2 SFP 10G |
| 20 | `eth20` | **100G CPU 上联口**，内部，不对外 |

BSP 端口表里 `0 = DEBUG(LMT)`，`10/20/30/40/50 = ABIS1_0 ~ ABIS5_0`，对应 ETH1~ETH5 的前传接口。

注意：`eth0` 和 `eth200` 挂在 `eth1` 上是 **macvlan 接口（bridge 模式）**，不是 802.1Q VLAN。`ip -d link` 可以看到。管理 IP `192.254.1.16/16` 配在 `eth0:1` 上。

## 指示灯

| 板卡 | 灯 | 状态 | 含义 |
|---|---|---|---|
| VSW | RUN | 慢闪 0.3s | 单板运行正常 |
| VSW | RUN/M-S | 快闪 0.07s | 外部通讯异常 |
| VSW | M/S | 常亮 | 单板主用（快闪 = 自检中） |
| VSW | REF | 常亮 | 时钟锁定 |
| VSW | ETH（光） | 红常亮 | 底层物理链路正常（灭 = 光模块不在位） |
| VSW | ETH（电）/LMT | 左 = 链路 右 = 数据 | 左灭 = 断链，右慢闪 = 有数据 |
| VBP | OF/EOF | 红慢闪 | 光模块接收无光（LOS） |
| VEM | RUN | 快闪 | 与 VSW 板通信链路断 |
| VPDc1 | PWR | 灭 / 亮 | 无输入 / 正常 |
| VPDc1 | ALM | 常亮 | 输入过压或欠压 |
| VFC1 | ALM | 常亮 | 输入过压或欠压 |

## 线缆

原厂是专用连接器。自制的话先量通断再接，引脚定义随批次会变。电源线反接会烧板。建议用原厂线应急除外。

## 散热

基站级设计，风噪不小。别塞密闭柜子，环境温度控制在 35°C 以下。CPU 待机温度实测 26.8°C（acpitz）。
